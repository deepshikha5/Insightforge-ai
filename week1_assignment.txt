1. Why do we create a virtual environment?
We create a virtual environment so each project has its own isolated Python setup. This keeps dependencies for one project from conflicting with another project on the same computer. It also helps ensure that everyone uses the same versions of the packages required by the project.

2. What does `app.main:app` mean in the Uvicorn command?
`app.main:app` tells Uvicorn where the FastAPI application object is located. It means: look in the `app` package, inside the `main.py` file, and use the variable named `app`. In this project, that variable is the FastAPI instance created in `app/main.py`.

3. What is the job of the `/health` endpoint?
The `/health` endpoint checks whether the application is running properly. It is a small monitoring endpoint that returns a simple success response such as `{"status": "ok"}`. This helps confirm that the server is alive and responding as expected.

4. Why use an automated test when you can open the endpoint in a browser?
A browser check is useful for manual testing, but an automated test is better because it is repeatable and reliable. It can be run quickly in CI or during development without human effort. Automated tests also catch regressions and help confirm that behavior still works after code changes.

5. Why do we use `.gitignore`?
We use `.gitignore` to prevent unnecessary or sensitive files from being added to Git. This includes things like virtual environments, cache folders, local editor files, and compiled Python files. It keeps the repository clean and avoids clutter or accidental commits.

6. What is Ruff checking?
Ruff is a Python linter and formatter tool. It checks the code for common issues such as syntax problems, unused variables, bad imports, style violations, and some quality issues that can lead to bugs. In this project, running `ruff check .` verifies that the code meets the configured Python quality rules.

Short summary:
A virtual environment keeps dependencies isolated, `app.main:app` points Uvicorn to the FastAPI app, the `/health` endpoint confirms the service is alive, automated tests are more reliable than manual browser checks, `.gitignore` keeps the repo clean, and Ruff helps catch code quality problems before they become bigger issues
